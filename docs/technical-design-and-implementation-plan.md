# 执行决策分离：最小实验设计与实施计划

- 日期：2026-10-17
- 依据：[需求梳理](./requirements.md)。本版收缩前版工程规模，保留已确认的架构与失败语义。
- 当前状态：M1 [一对闭环](./step-1-results.md)、M2 [两组并发隔离](./step-2-pair-isolation-results.md)、M3 [明确断线恢复](./disconnect-reconnect-results.md)及[心跳检测静默失联](./heartbeat-silent-loss-results.md)、M4 [epoch 切换与迟到事件](./epoch-late-events-results.md)、M5 [远程工具忽略取消](./uncancellable-tool-results.md)、M6 重拨额度及[超时与结果竞争](./timeout-result-race-results.md)分项已验证。以下仍包含尚未实现的独立 cancel 消息及其他故障验收约定。

## 1. 最小实验到底做什么

只证明：**同一份大脑决策代码，可以通过网关调用远端执行端；多组绑定不串线；断线后旧调用失败且不会偷偷重放。**

**当前交付范围：**两组绑定、同一大脑流程、echo 与 wait，以及明确断线／心跳发现静默失联后的有限重连。网关保留健康侧连接，发送空 epoch 作废旧通道；端点结束旧调用、尝试取消旧执行，只为新的调用恢复连接。当前没有独立 cancel 消息，调用超时仍通过关闭本次 WS 请求取消。当前可运行命令见 [README](../README.md)。

完整最小实验分三步，最终范围固定为：

| 项目 | 最小选择 |
| --- | --- |
| 进程 | 一个 Gateway、两个 Brain、两个 Executor；每个端点进程一个逻辑实例。 |
| 绑定 | A、B 两组静态一对一绑定；本机先以独立 Brain 进程验证，不增加单进程多实例调度。 |
| 语言与组织 | Go、一个 module、一个程序、三个角色入口；现有职责分到四个内部包。 |
| 工具 | 产品提供合作取消的 `echo` 和 `wait`；M5 在测试中注入有限时长忽略取消的 wait，不增加运行参数。 |
| 调用 | 每个绑定一次最多一个调用，返回一次 JSON 结果。 |
| 鉴权 | 手工配置，每个 `(pair, role)` 独立 token；不开发账号或配对系统。 |
| 环境 | 当前本机，通过真实 WS 通信；真实云端部署放到下一步。 |
| 故障策略 | 旧调用失败、尝试取消、结果丢弃；有限恢复连接，只执行新调用。 |

不做配置生成器、`experiment` 命令、自动进程编排、通用 testkit、故障代理平台、报告系统、指标系统、SDK 包装或压力测试。也不做真实模型、真实 Shell、流式输出、交互式终端、安装升级、多租户与多网关。

Go 与 `github.com/coder/websocket` 沿用前版选择；实现时固定兼容的依赖版本即可，不展开技术选型。WS 库的读循环、Ping 与超时行为按[官方文档](https://pkg.go.dev/github.com/coder/websocket#Conn)使用。

## 2. 文件与职责

最初以单包验证闭环；2026-10-18 按现有职责整理为四个内部包，并将测试集中到 `test/`。这次只调整文件归属、导入和跨包名称，没有新增业务能力或抽象层。

```text
main.go                         # 仅调用 app.Main
internal/app/app.go              # gateway / brain / executor 参数、准备和启动
internal/app/brain.go            # 同一份 echo → wait 流程及逐行输入
internal/gateway/binding.go      # 静态绑定与凭证环境变量
internal/gateway/gateway.go      # 鉴权、配对、在线转发
internal/endpoint/client.go      # 两端共用连接、当前代次、有限重连
internal/endpoint/executor.go    # 统一接口、Local / Remote、当前调用等待
internal/endpoint/executor_endpoint.go # 一个执行槽、取消与丢弃旧结果
internal/endpoint/tools.go       # echo、wait
internal/transport/protocol.go   # 两种外层消息、工具消息及共用常量
internal/transport/heartbeat.go  # 每条 WS 独立 Ping/Pong
internal/transport/frame.go      # 有限超时的 WebSocket 写入
test/                          # 原有 7 个 *_test.go
bindings.example.json
```

依赖方向为 `main → app → gateway / endpoint → transport`。网关处理函数只能读取路由外层，不解释工具名、参数或执行状态。`app.RunBrain` 只调用 `endpoint.Executor`；WS 和重连留在 `endpoint.Client` 与 `RemoteExecutor`。

测试仍使用原生 `go test ./...`。移到独立目录后，原有白盒检查通过 `internal` 包中必要的导出名称访问原对象，不增加测试框架、复制实现或临时生成源码。
一个逻辑大脑对应一个 RemoteExecutor、一条 WS 和一个当前等待槽；不能让两个逻辑大脑共用一个全局等待槽。Executor 每进程一个执行身份、一个实际执行槽。

## 3. 统一调用接口

```go
type Executor interface {
    Call(ctx context.Context, tool string, input json.RawMessage) (json.RawMessage, error)
}
```

大脑执行同一段固定流程，例如先 echo，再 wait；只在启动时选择 LocalExecutor 或 RemoteExecutor。接口只表达成功或带原因的失败，不暴露绑定、socket、通道代次和重连。

- Local 与 Remote 使用同一套模拟工具及参数校验；错误至少能区分不可用、忙碌、超时／取消和工具失败。
- 未就绪或已有调用时立即失败，不等上线、不排队；连接就绪等待只放在启动阶段。
- request_id 由执行器生成；登记当前等待后再发送，防止快速结果先到。
- 调用结果、超时、断线和代次变化只能结束等待一次；迟到结果不得修改终态。
- Remote 的 `WaitResult` 在任意等待分支唤醒后统一检查调用 context、原通道，再接受结果。即使结果已入队，终态检查时调用 context 已超时也只能返回失败；`Call` 返回时清除 pending，后续旧结果不能重新交付。该检查已用结果先到、超时先到和两者同时就绪三个时序验证。
- 超时或主动取消时结束等待，尽力取消执行；已开始的操作可能继续，不能据失败推断未执行。
- 若后续让 LocalExecutor 接入忽略取消的工具，也必须及时结束调用方等待，并保留实际执行占用直到工具退出。当前 Local 只装配合作退出的工具，本轮 M5 仅验证远程执行端。

不设计完整错误码体系或“是否可以安全重试”的自动判断。系统没有业务自动重试；后续重新调用可能重复产生副作用。

## 4. 最小 WS 协议与寻址

### 4.1 接入

两端主动访问 `/ws?pair=A&role=brain` 或 `/ws?pair=A&role=executor`，在 `Authorization: Bearer ...` 中提供本端凭证。身份信息可在 URL 中，凭证不能放在 URL 或日志中。

网关验证 token 对应这个 pair 与 role，再绑定到唯一对端。这里 `(pair, role)` 就是首版稳定的逻辑端点身份，不额外建立 brain_id、executor_id 等多套 ID。第二个同身份连接被拒绝，不接管已有连接；握手登记须原子占位，失败释放。

本机只监听回环地址，使用 WS；跨主机再配置 WSS。配置只有两组绑定及独立凭证引用，不做运行中换绑。

### 4.2 只保留两个外层消息

```json
{"type":"state","epoch":"随机通道标识"}
```

`epoch` 非空表示两端已形成通道，空字符串表示对端不可用。任一端断开，当前 epoch 作废；双方重新就绪时生成全新的随机 epoch。它代表双方组成的通道，不能只用 Executor 自己的拨号次数代替。

```json
{"type":"data","epoch":"随机通道标识","body":{"kind":"call","id":"r1","tool":"wait","input":{"ms":1000},"timeout_ms":15000}}
```

`data.body` 只由端点解释。网关校验当前 socket、绑定、epoch 与消息大小后，转发原消息，不解析 body 的工具语义。

state 只能由网关发出；客户端只能发送 data，未知或非法外层消息被拒绝，不能伪装成网关控制消息。

心跳使用 WS 自带的 Ping/Pong 控制帧，不新增 JSON 心跳消息，也不转发给配对端。每段连接的网关和端点各自发起探测；读循环持续处理控制帧，业务空闲或工具正在执行都不停止保活。

完整设计的业务内容只有三种；当前只实现 `call`／`result`，`cancel` 暂未实现：

| kind | 内容与行为 |
| --- | --- |
| `call` | id、tool、input、timeout_ms；Executor 按收到时的剩余调用预算运行工具。 |
| `result` | 相同 id，以及 output 或 error 二选一；只交付给同 epoch、同 id 的当前等待。 |
| `cancel` | 相同 id；只取消该 epoch 的当前任务，不确认、不重试、不保存。 |

调用方以本地 deadline 控制等待；Executor 从接收时开始计时，不依赖跨机器时钟一致。网络延迟可能导致 Executor 更晚退出，因此仍需要取消与迟到结果丢弃。

后续的取消消息是一次在线尝试，不能排队等待下次连接。当前超时／主动取消直接关闭该调用所属的 socket，通过失联触发 Executor 取消；后续有独立 cancel 时，发送失败仍可使用这一退路。每连接最多一条正在写的消息，不为取消生成无限后台任务。

不做 welcome、业务 ACK、结果查询、恢复游标、route.error、事件 revision 或网关实例 ID 等独立协议。网关拒绝过期数据后直接丢弃；状态消息或断线让端点结束旧等待，调用超时负责兜底。

### 4.3 保留必要的顺序与旧连接保护

简化协议依赖以下实现约束，不能一起删掉：

1. 每个 Pair 的登记、状态更新、状态发送和应用消息转发串行处理。可以使用 Pair 自己的锁配合有时限写入；绝不持全局锁做网络 I/O。
2. 双方就绪时，先向 Executor 发送非空 epoch，再向 Brain 发送；同一 socket 的应用消息按顺序写入。这样 Executor 先看到通道状态，再看到调用。
3. 任一步失败就作废该 epoch。没有任何数据保留到下一次连接。
4. 断线清理与端点读循环回调都核对自己仍是当前 socket；旧连接回调不能清理或改写新连接。
5. 端点收到不同 epoch 时，先结束旧等待、取消旧执行上下文，再接纳新 epoch。即使漏掉空 epoch 状态，也必须这样处理。
6. 旧结果在发送前、网关转发前及大脑交付前核对 epoch；已在网络中的字节无法撤回，不能因此承诺零副作用。

失败清理使用取消与强制关闭，不在 Pair 锁内等待对端完成关闭握手，避免读循环和清理相互等待。

每个 Pair 的短时串行写入只会影响这一对。单调用、小消息实验足够使用这种直接实现，不为吞吐量引入事件总线和发送队列。

## 5. 连接状态与固定边界

```text
连接中 → 等待对端 → 就绪
   ↓          ↓       ↓ 失联
拨号失败   等待超时   旧调用失败、取消旧执行
   ↓          ↓       ├─ 自身 WS 断开：有额度才重拨
有额度重拨    停止      └─ 对端离线：保持本端 WS，有限等待
   ↓
额度耗尽：停止，需重启端点
```

非“就绪”状态的新调用立即失败。对端离线时不反复断开自身仍正常的 WS。状态恢复只允许新的调用，不恢复旧等待。

停止自动恢复只影响当前逻辑端点，不能因 A 额度耗尽而退出整个 Brain 进程、连带停止 B。

首版用代码常量，不做参数配置体系：

| 边界 | 实验默认值 |
| --- | --- |
| 心跳 | 网关和端点各自每 1 秒 Ping，最多等 2 秒 Pong；失败取消该 socket 的读循环并关闭连接。 |
| 拨号 | 每次最多 5 秒；初次拨号之外，本次端点运行最多再拨 3 次，间隔 5 秒。 |
| 重连额度 | 成功不重置；耗尽需重启端点。主动停止不会自动重连。 |
| 等待对端 | 本端已连接时最多等 30 秒；超时关闭本端连接并停止自动恢复。 |
| 写入 | 最多 2 秒，包括取得写入权；失败结束当次发送，不缓存、不重试。 |
| 调用 | 缺省 15 秒；实验 wait 最多运行 30 秒。 |
| 大小 | 完整 WS 消息最多 64 KiB；共享输入／输出校验保留封装余量。 |

这些值足够跑实验，实施遇到实际问题再调整。总恢复耗时受有限拨号次数、每次拨号及等待期限共同限制，不另建指数退避、抖动、稳定窗口重置和多层计时器。

心跳从原计划的 5 秒／10 秒收窄为本机实验用的 1 秒／2 秒，使失联检测明显早于 15 秒调用期限；正常调度下约 2–3 秒发现持续的静默失联，调度暂停或写入阻塞可能使观察时间更长，不能当作硬实时上限。心跳绑定单条 socket 的生命周期，不拿 Pair 锁等待 Pong，也不借用工具 deadline；旧连接的心跳不能关闭新连接。检测后复用原失联状态机，保持重拨额度、epoch 与不重放语义。

这是刻意收窄的实验恢复策略：运行很久后也不会自动补充重连额度。它符合有限恢复要求，但不作为生产重连策略。

## 6. 不能因简化而删除的故障规则

| 情况 | 最小处理 |
| --- | --- |
| 对端离线或当前无法发送 | 本次调用失败，不留消息等对端恢复。 |
| 执行中失联／epoch 改变 | 大脑结束旧等待；Executor 取消旧上下文、丢弃旧结果。 |
| 工具不响应取消 | 调用仍失败；旧工具实际退出前继续占用执行槽，新调用返回忙碌。 |
| 超时与结果同时到达 | 使用一个结束入口，核对 ctx 和 deadline，只提交一次结果。 |
| 慢接收方 | 有限写入，超时关闭故障连接；不阻塞其他 Pair 的锁。 |
| 同身份重复接入 | 拒绝第二条有效连接，防止两个执行者同时在线。 |
| 大消息 | 解码前限制整条消息大小，拒绝超限；不无限读取。 |

工具执行放在独立 goroutine，不能堵住 WS 读循环和心跳。共用读循环使用连接生命周期 context，不能误用某次调用的超时 context。网关只保存当前连接、绑定和 epoch；端点只保存当前等待／执行槽，没有完成记录、结果缓存或持久化。

网络库的瞬时传输缓冲与当前请求的工作内存仍存在，但它们不能成为业务队列，也不能跨连接保存消息。取消只是信号，不等于回滚或立即停止工具。

## 7. 六组轻量验收

不建立测试平台。用实际进程演示闭环，加少量 Go 测试直接触发连接关闭和状态变化；精确竞态使用很小的测试同步点，工具启动日志用于确认时机。

| 编号 | 验证动作 | 通过标准 |
| --- | --- | --- |
| M1 接口与闭环 | 同一大脑流程分别使用 Local 和 Remote，调用 echo、wait | 只改执行器装配；远程经过真实 WS 与网关，得到相同工具结果。 |
| M2 两对隔离 | A、B 同时调用，各跑少量带不同标记的请求；顺手检查错误凭证和重复接入 | 不串线；错误身份和第二条有效连接被拒绝。无需 10 对、1,000 次压测。 |
| M3 失联与恢复 | A 的调用开始后断开链路，再恢复；B 继续调用。明确关闭 WS 与双向丢弃字节的静默失联均已验证，分别覆盖 Brain／Executor 链路 | A 旧调用失败且不重放，已知离线的新调用立即失败；恢复后只执行新调用，B 可继续工作。 |
| M4 代次与迟到事件 | 已验证两端 socket 都不变时直接应用新 epoch；另分别重连 Brain／Executor，在新调用执行中注入旧清理和旧结果 | 旧执行被请求取消、旧等待失败；旧回调不删除新路由，旧结果不改变新调用，B 不受影响。 |
| M5 取消失败 | 测试注入有限时长忽略取消的 wait；在它退出前恢复通道并调用。已通过真实 WS 分别验证 A Brain／Executor 断线 | 新调用忙碌；旧工具退出后容量恢复；旧结果丢弃，B 不受影响，不伪装已停止。 |
| M6 有界失败 | 网关不可达时观察重拨；工具超时，超时后再返回结果 | 自动重拨额度用完就停止；调用只失败一次，不被迟到成功覆盖。 |

上述场景复用同一套简单工具与日志；不再增加通用代理、测试时钟或机器可读报告系统。大小限制、写入超时等边界用针对性的短测试核对，不开展全面性能或资源基准测试。

当前配置为绑定数组，Brain／Executor 使用 `-pair` 选择其中一组。以下入口在各自进程运行；两份 Brain 需并发启动，完整命令与凭证示例见 [README](../README.md)：

```sh
go run . gateway
go run . executor -pair A
go run . executor -pair B
go run . brain -pair A -message A-only -wait-ms 800
go run . brain -pair B -message B-only -wait-ms 1200
```

本地对照只切换为 `-mode local`。配置手工从示例准备，凭证通过环境变量提供，不提供 init 命令。当前已有固定额度的自动重拨；每组独立故障实验重新启动端点，避免前一组消耗的额度影响后一组。用 `brain -stdin` 在同一进程中逐行显式提交新请求，失败输入不会重试。三个角色使用本机进程和回环网络；故障操作只针对本次实验进程，不修改系统防火墙。

最终在一份短验收记录中列出环境、命令、每组通过／失败与必要日志即可。不得把当前设计文字写成已通过结果。

## 8. 分三步交付，而不是一次铺完整工程

1. **先跑通一对。**统一 Call、Local／Remote、静态绑定、一次请求与结果，给出三个独立进程的运行证据。只实现所需文件，不提前建测试框架。
2. **再验证核心边界。**加第二对、有限重连、epoch 切换、取消和实际执行占用。每个新增规则都有对应的小验证。
3. **跑六组验收并收尾。**补必要的竞态检查、修复失败项、留简短运行记录，最小实验到此停止。

每一步先形成可运行、可检查的成果再推进。当前完成两组隔离、明确断线／静默失联后的失败／取消／恢复、重拨额度、远程工具忽略取消时的执行槽检查，以及同连接换代和迟到事件检查，停在此处；不据此宣称全部竞态已经验证，也不增加其他工程化能力。

## 9. 设计复核结论

### 前置决策

当前没有必须再由用户拍板、才能开始最小实验的业务问题：绑定粒度、静态凭证、模拟范围、调用接口、失败语义、取消边界和本机部署都已明确。Go、两组绑定、单调用、一次性结果及固定常量按最小实验默认处理。

后续真的接入云端、真实智能体或真实工具时，才需要明确服务器、真实工具协议、系统权限及支持平台；这些不作为当前开工的前提。

### 本轮审查发现与处理

- **前版范围偏重：**最初删除了为未来复用预设的多层工程结构、自动实验命令、配置生成、通用故障设施与大规模用例。当前四个内部包是读完现有代码后按已有职责整理，不恢复上述能力。
- **需求到技术规则的具体缺口：**需求已要求“新代次主动取消旧执行”，前版技术章节主要写了 down 通知和本端失联。本版明确任何 epoch 变化都先取消旧上下文，不要求旧 down 必达；M4 单独验证。
- **已有防护，继续保留：**身份与绑定检查、旧 socket 清理保护、旧结果隔离、有限等待、单次结束、写入与消息大小上限。它们不扩展产品功能，直接保护实验结论。
- **已接受的取舍：**无结果恢复，断线失败不代表未执行，取消不保证回滚，不提供恰好执行一次。它们不再反复作为待讨论项。

本机模拟实验可以暴露关键时序问题，不能仅靠文档保证没有未知缺陷。先做上述小实验，用实际结果决定是否值得进入跨主机验证；不提前为所有假想情况建工程。
