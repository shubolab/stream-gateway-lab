## 用户本轮问题

> epoch 这个词的本意是什么？在常见的网络协议中有哪些地方用了这个词？在本系统中怎么通俗易懂地理解它的含义？

## 资料与事实

- 词义有“新时期的开端／一个时期”和“选定的时间参考点”等含义。
- NTP 使用时间参考点的含义；DTLS 使用密码状态代次；Kafka 和 Redis Cluster 的协议也有领导权、事件或配置代次相关字段。
- 本工程的 epoch 由网关生成，用于标识双方的一轮有效通道，实际是随机字符串，不比较大小。
- Brain 重新接入时，Executor 的健康 WS 可以保留，但整组通道仍要换 epoch。

上述外部来源的直接链接、差异说明以及源码定位已放入[epoch 专题](../06-epoch-explained.md)。不能由“其他系统也叫 epoch”推断本实验具有它们的选举、持久化或密码协议机制。

## 本轮解释观点

助手建议把三个词放在同一个“固定搭档多次连线”的例子里理解：`pair` 是固定搭档，`epoch` 是本次连线的场次号，`id` 是场内的一次工具调用编号。

这进一步回答讨论 001 的 Q001：pair 无法区别新旧场次；id 关联单次调用，epoch 则为整轮通道、旧调用取消与迟到消息隔离提供共同边界。

“场次号”是帮助理解的比喻。代码实际使用随机标识，不表达第几次连线，也不度量持续时间；是否重命名变量不在本轮决定范围内。
